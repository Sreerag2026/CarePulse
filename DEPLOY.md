# Deploying CarePulse

Steps to get the site live at `https://carepulse-vr1l.onrender.com`, optionally on your own
`www.` domain.

## 1. MongoDB Atlas

The Render logs show `bad auth : authentication failed`, which means the password in
`MONGO_URI` is wrong. Set a new one:

1. Sign in at https://cloud.mongodb.com and open the CarePulse project.
2. **Security → Database Access** → find the database user → **Edit**.
   - If there's no user, click **Add New Database User**, choose **Password**, and enter a username.
3. Click **Edit Password → Autogenerate Secure Password**, then copy the password.
   An autogenerated password has only letters and numbers, so it won't need URL-encoding.
4. Under **Database User Privileges**, choose **Read and write to any database**, then click **Update User**.
5. **Security → Network Access → Add IP Address → Allow Access from Anywhere** (`0.0.0.0/0`) → **Confirm**.
   Render's outgoing IP addresses change, so a fixed IP won't work. Wait until the entry shows **Active**.
6. **Database → Clusters → Connect → Drivers → Node.js** and copy the connection string:

   ```
   mongodb+srv://<username>:<db_password>@cluster0.xxxxx.mongodb.net/?retryWrites=true&w=majority&appName=Cluster0
   ```

7. Replace `<db_password>` with the password from step 3, including the `<` and `>`.

**Using your own password?** URL-encode its special characters:

| Character | Write it as |
| --- | --- |
| `@` | `%40` |
| `:` | `%3A` |
| `/` | `%2F` |
| `?` | `%3F` |
| `#` | `%23` |
| `%` | `%25` |

You don't need to add a database name to the string. The server uses a database called `carepulse`.

## 2. Generate AUTH_SECRET

`AUTH_SECRET` signs login tokens. Without it, everyone is logged out whenever Render restarts the
server. Generate one:

```bash
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
```

Copy the 64-character output. Keep it private; anyone who has it can forge logins.

## 3. Add both to Render

1. Go to https://dashboard.render.com → **CarePulse** service → **Environment**.
2. Under **Environment Variables**, click **Edit**, then add or update:

   | Key | Value |
   | --- | --- |
   | `MONGO_URI` | connection string from step 1 |
   | `AUTH_SECRET` | value from step 2 |
   | `DOCTOR_SIGNUP_CODE` | code doctors enter to register (see step 6) |
   | `DEVICE_API_KEY` | *(optional)* a secret the monitoring device sends when posting readings |

   Leave `PORT` as it is. Render handles it.
3. Click **Save, rebuild, and deploy**.

## 4. Push the code

From the project folder:

```bash
git status
```

Check that `.env` is **not** listed; it holds secrets and is git-ignored. Then:

```bash
git add .
git commit -m "Restore API, serve frontend, add login tokens"
git push origin main
```

Render deploys automatically if **Settings → Build & Deploy → Auto-Deploy** is on. Otherwise
click **Manual Deploy → Deploy latest commit**.

## 5. Check it's live

1. **Render → Logs** should show:

   ```
   🚀 Server running on port ...
   ✅ Connected to MongoDB (database: carepulse)
   ```

   If it shows `bad auth`, re-check step 1. If it shows `AUTH_SECRET is not set`, re-check step 3.
2. Open https://carepulse-vr1l.onrender.com/api/health. It should show `"database":"connected"`.
3. Open https://carepulse-vr1l.onrender.com and register a test parent.

The free plan sleeps after inactivity, so the first visit can take up to a minute.

## 6. Doctor accounts

Doctor accounts can see every patient, so doctors need a **registration code** to sign up.

1. Generate a code:

   ```bash
   node -e "console.log(require('crypto').randomBytes(6).toString('hex'))"
   ```

2. **Render → CarePulse → Environment → Edit** → add `DOCTOR_SIGNUP_CODE` with that value → **Save, rebuild, and deploy**.
3. Give the code only to real doctors. They register on the website under **Doctor Login → New doctor? Register**.
4. To stop new doctor sign-ups, delete the variable or change the code. Existing doctors can still log in.

Until `DOCTOR_SIGNUP_CODE` is set, the registration page says "Doctor registration is closed".

**From the command line instead.** This also resets a forgotten doctor password. Render's Shell
isn't available on the free plan, so run it on your own computer, pointed at the same Atlas
database. Add this line to your local `.env`:

```
MONGO_URI=<same connection string as on Render>
```

Then run:

```bash
npm install
npm run create-doctor -- HOSP-2291 DR-0148 "a-strong-password" "Dr. Priya Nair"
```

## 7. Optional: your own www domain

You need a domain you own, such as `carepulse.in`. The site calls its own server, so no code
changes are needed.

1. **Render → CarePulse → Settings → Custom Domains → Add Custom Domain** → enter `www.carepulse.in`.
2. Render shows the DNS record to create. At your domain registrar (GoDaddy, Hostinger, Namecheap, …), add:

   | Type | Host / Name | Value |
   | --- | --- | --- |
   | CNAME | `www` | `carepulse-vr1l.onrender.com` |

3. Back in Render, click **Verify**. Once DNS updates (minutes to a few hours), Render issues the
   HTTPS certificate automatically.
4. To make the bare domain (`carepulse.in`) work too, add it in Render as well and create the
   record Render shows for it (an A or ALIAS record).
